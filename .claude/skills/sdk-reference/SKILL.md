# Polaris WebOffice SDK 실무 참고 (사실 확인용)

`resume-guideline`이 "어떻게 써야 하는가(작성 방법론)"를 다룬다면, 이 문서는 "실제로 어떻게 일하고 있는가(사실)"를 다룹니다. 이력서 항목을 새로 쓰거나 검토할 때, 여기 없는 내용을 임의로 지어내거나 본인 기여 범위를 넘겨짚지 말고 이 문서와 대조하세요. 이 문서에 없는 새로운 사실이 대화 중 확인되면, 아래 형식에 맞춰 이 문서에도 추가해 나갑니다(누적 업데이트).

## 이슈 처리 흐름 (B2B 파트너사 대응)

- B2B 파트너사의 기술 문의/이슈는 Outlook 메일로 인입됨.
- 먼저 내부에서 재현을 시도함. **재현이 안 되면** 원인 파악을 위해 업체에 추가 정보를 요청함 — 문제가 발생하는 실제 문서(재현 가능한 샘플), 특정 API 호출 시점/순서, 가능하면 화면 녹화·스크린샷. **재현이 되면** 아래처럼 UI/엔진 레벨을 구분해 처리함.
- **UI 레벨 이슈**로 판단되면 본인이 직접 SDK 저장소 코드를 조사·수정.
- **엔진(WASM/C++) 레벨 이슈**로 판단되면 본인이 직접 수정하지 않음 — 원인 분석 결과(SDK가 어떤 엔진 API를 어떤 데이터로 호출하고 있는지 등)를 근거로 엔진팀에 이슈 코멘트를 남겨 원인 파악과 수정을 요청하는 방식으로만 관여. 엔진 소스 저장소(private, `PolarisOfficeRnD/PolarisOffice8.0`)는 읽기 전용으로만 참조.
- 이 흐름은 `payload/companyProject.ts`의 "SDK MCP 도구와 Claude Code 스킬 기반 자동화" 항목(문의 대응 → 코드 수정 → 배포·라이선스 운영 3단계 분기)에 이미 반영돼 있음. 별도 이력서 항목으로 중복 서술하지 않는다.

**이력서 작성 시 주의**: 엔진 이슈는 "분석 후 코멘트로 소통"까지만 본인 기여다. "엔진 이슈를 해결/수정했다"처럼 쓰지 않는다.

## 기능/API 개발

- 월 10건 이상 진행하는 것으로 실측 확인됨. 카테고리: 오피스 기능 추가, 기능 수정, 버그 수정, API 추가 지원, API 오류 수정. `payload/companyProject.ts`의 "월 10건 이상 규모의 API·UI 기능 지속 개발로 SDK 완성도 제고" 항목에 반영됨.
- 예: 문단 간격 기능 지원(신규), 단축키 지원(신규), 문서 내 정렬이 제대로 적용되지 않는 버그 — 단, 이 정렬 버그는 **엔진에서 수정**한 사례로, 본인이 직접 고친 게 아니라 엔진팀에 전달해 해결된 케이스임(이력서에 본인 기여로 쓰지 않도록 주의).

## 자주 오는 문의 유형 (참고용 — 이력서 항목 아님)

아래는 기존 이력서 항목("B2B 파트너사 SDK 납품 및 기술 지원", "SDK MCP 도구와 Claude Code 스킬 기반 자동화")이 이미 포괄하는 하위 사례들. 새 이력서 항목으로 쓰지 않되, 면접에서 "기술 지원이 구체적으로 뭐였나요?" 같은 질문의 답변 근거로 참고.

- **폰트 정책 문의 답장**: 웹오피스 폰트 정책 관련 문의에 답장. 반복적/루틴한 CS 성격.
- **API 사용법 샘플 코드 작성**: 업체가 "이런 기능을 이렇게 구현하고 싶다"고 문의하면, SDK API(`insertTable`, `SetCurFieldName`, `TableInsertLowerRow`, `PutFieldText` 등)를 조합한 샘플 코드를 작성해 전달. `vendor-mail-reply` 스킬의 cookbook(과거 코드 예제 재사용) 대상.
