# 재현 불가 이슈 — 추가 정보 요청 메일

업체가 보고한 버그를 내부에서 재현하지 못해, 재현에 필요한 추가 정보를 요청하는 회신 초안을 작성하는 스킬입니다. **이 스킬은 초안 작성까지만 하며, 실제 메일 발송은 절대 하지 않습니다.**

## 왜 이런 구조인가

- **발송하지 않는 이유**: `vendor-mail-reply`와 동일합니다. 업체와의 커뮤니케이션은 항상 사용자가 최종 검토 후 직접 발송해야 합니다.
- **원본 스레드를 이어서 회신하는 이유**: 이 팀의 관례상(`mail-to-jira-issue` 참고) Jira 이슈는 업체 CS/영업 담당자가 전달한 메일을 근거로 등록됩니다. 즉 이슈의 "원출처"는 메일이고, 재현 요청도 그 메일 스레드를 이어가야 업체 쪽에서 맥락 없이 새 메일로 받는 혼란이 없습니다.
- **재현 못 한 이유를 추측해서 쓰지 않는 이유**: "재현이 안 된다"는 사실만 전달하고, 왜 안 되는지는 업체에게서 받을 정보로 판단해야 합니다. 원인을 섣불리 짐작해서 메일에 쓰면 업체를 오도할 수 있습니다.

## 워크플로우

### 1. 대상 이슈/메일 특정

시작점은 둘 중 하나입니다:
- **Jira 이슈로 시작** (예: "WO-5542 재현이 안 돼") → `mcp__atlassian__getJiraIssue`로 `description`, `summary`, `comment`를 조회합니다. `mail-to-jira-issue` 템플릿을 따랐다면 description의 "업체 문의내용" 섹션에 원문 인용과 업체 담당자 이메일(예: `[VOC] xxx@vendor.com`)이 남아있습니다.
- **메일로 시작** (메일을 붙여넣거나 발신자/제목으로 지목) → `mail-to-jira-issue`와 동일한 방식으로 `mcp__outlook__list-mail-messages`/`get-mail-message`로 찾습니다.

Jira 이슈로 시작한 경우, description에 남은 회사명/제품명/문의자 이메일 등 키워드로 Outlook에서 원본 스레드를 검색해 실제 회신 대상(보통 최종 발신자가 아니라, 사내에서 이 이슈를 전달해준 CS/영업 담당자)을 찾으세요. 이미 그 담당자와 주고받은 이전 답장("검토 후 회신드리겠다" 류)이 있으면 그 스레드를 그대로 이어갑니다. 여러 스레드/후보가 나오면 반드시 사용자에게 확인받으세요.

### 2. 재현 시도 확인

사용자가 이미 이번 대화에서 재현 시도 내용(무엇을 시도했는데 안 됐는지)을 말했다면 그대로 사용하고, 없으면 간단히 물어보세요 — 다만 이미 "재현이 안 된다"는 사실 자체는 사용자가 말해준 것이므로 재확인은 가볍게만 합니다.

### 3. 요청할 정보 항목 선정

문의 내용에 따라 아래 체크리스트에서 실제로 필요한 항목만 골라 요청하세요 (관련 없는 항목까지 기계적으로 나열하지 않습니다):

- **재현용 파일/문서** — 문제가 발생하는 실제 문서(HWP/WORD/SHEET/SLIDE), 또는 최소 재현 가능한 샘플 문서. 민감한 문서라면 문제 부분만 남긴 축소본도 가능하다고 안내
- **상세 재현 절차** — 어떤 기능/옵션을 사용 중인지, 조작 순서, 클릭/드래그 위치 등 구체적으로
- **관련 API 호출 코드/시점** — 문제와 관련된 SDK API를 언제·어떤 순서로 호출하는지 (예: `setEditMode` 같은 옵션 호출 전후 코드)
- **환경 정보** — 브라우저 종류/버전, OS, SDK(또는 엔진) 버전
- **화면 녹화/스크린샷** — 가능하면 현상을 보여주는 영상이나 캡처

### 4. 답장 초안 제시

제목은 원본 스레드 제목에 `Re:`를 붙여 그대로 유지합니다. 본문은 정중하고 간결하게, 아래 흐름으로 작성하세요:

1. 인사 + "말씀해주신 OO 건, 내부적으로 재현을 시도했으나 아직 확인하지 못했다"는 사실 전달
2. 3단계에서 고른 요청 항목을 번호 목록으로 정리
3. 맨 마지막에 아래 두 문장을 고정 마무리 문구로 넣습니다 (표현을 바꾸지 말고 그대로 사용):

   확인 가능하신 부분만 전달해주셔도 괜찮습니다.
   전달해주신 내용을 바탕으로 다시 확인해보겠습니다. 번거로우시겠지만 확인 부탁드립니다.

대화창에 텍스트로 제시하고, **발송은 하지 않습니다.**

### 5. Jira 이슈에 기록할지 확인

초안을 제시한 후 이렇게 물어보세요: "이 이슈에 재현 불가 + 추가 정보 요청했다는 코멘트를 남길까요?"

사용자가 승인하면 `mcp__atlassian__addCommentToJiraIssue`로 짧게 기록합니다 (예: "내부 재현 실패. 업체에 재현 문서/상세 절차/환경 정보 요청 메일 발송함."). 이슈 상태(status)를 바꾸는 것은 이 스킬의 범위가 아니므로, 사용자가 명시적으로 요청하지 않는 한 `transitionJiraIssue`는 호출하지 마세요.
