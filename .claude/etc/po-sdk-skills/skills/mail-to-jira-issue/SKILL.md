# Mail → Jira Issue (WO 프로젝트)

Outlook 메일 하나를 골라서 WO 프로젝트의 Jira 이슈로 등록하는 스킬입니다. 이 프로젝트(폴라리스오피스 SDK)의 이슈 등록 관례를 따르므로, 임의로 다른 형식을 쓰지 말고 아래 규칙을 그대로 적용하세요.

## 왜 이런 구조인가

- **제목 형식이 고정된 이유**: `[업체명][엔드유저][포맷] 요약` 형식은 이 팀이 이슈를 업체/엔드유저/포맷(HWP, WORD, SHEET, SLIDE) 기준으로 빠르게 필터링하기 위해 쓰는 관례입니다. 임의로 다른 형식을 쓰면 기존 이슈들과 일관성이 깨집니다.
- **본문을 원본 그대로 넣는 이유**: 담당자가 나중에 원본 메일 없이도 이슈만 보고 맥락을 재구성할 수 있어야 합니다. 요약하거나 재구성하지 말고 메일 내용을 최대한 그대로 옮기세요.
- **첨부파일을 업로드하지 않는 이유**: 현재 연결된 Jira MCP 도구(`createJiraIssue`, `editJiraIssue`)에는 파일 업로드 API가 없습니다. 실제 파일을 올리려고 시도하지 말고, 파일명만 본문에 나열하세요.
- **중복 체크를 하지 않는 이유**: 사용자가 의도적으로 중복 검사를 생략하기로 했습니다 (필요하면 사용자가 직접 기존 이슈를 확인함). 스킬이 나서서 기존 이슈를 검색하거나 막지 마세요.

## 워크플로우

### 1. 대상 메일 특정

사용자가 메일을 다음 중 하나의 방식으로 알려줍니다:
- 메일 내용을 대화에 직접 붙여넣거나 전달(forward)함 → 그대로 사용
- 발신자/제목/기간 등으로 설명함 → `mcp__outlook__list-mail-messages` 또는 `mcp__outlook__list-mail-folder-messages`로 `$search`(KQL, 큰따옴표로 감싸기) 또는 `$filter`를 이용해 검색
- 특정 메일 ID를 알려줌 → `mcp__outlook__get-mail-message`로 직접 조회

검색으로 여러 건이 나오면 반드시 사용자에게 후보를 보여주고 어떤 메일인지 확인받으세요. 확신 없이 임의로 하나를 골라 진행하지 마세요.

메일을 특정했으면 `mcp__outlook__get-mail-message`로 본문 전체와 발신자, 수신일시를 가져오고, 첨부파일이 있으면 `mcp__outlook__list-mail-attachments`로 파일명 목록을 가져오세요 (파일 내용을 다운로드할 필요는 없습니다 — 파일명만 본문에 기록하면 됩니다).

### 2. 이슈 필드를 사용자에게 확인

다음 항목은 메일만 봐서는 알 수 없으므로 반드시 사용자에게 물어보세요. 이미 이번 대화에서 이미 알려준 값이 있다면 다시 묻지 말고 재사용하세요.

- **업체명** — 제목 첫 번째 대괄호
- **엔드유저** — 제목 두 번째 대괄호. 없다고 하면 이 대괄호는 생략
- **포맷** — 제목 세 번째 대괄호. `HWP`, `WORD`, `SHEET`, `SLIDE` 중 하나 (사용자가 다르게 부르면 이 네 가지 중 맞는 것으로 정규화해서 물어보세요, 예: "엑셀" → SHEET, "파워포인트/PPT" → SLIDE, "한글" → HWP)
- **요약내용** — 대괄호 뒤에 오는 한 줄 요약
- **담당자(assignee)** — 이름이나 이메일을 받으면 `mcp__atlassian__lookupJiraAccountId`로 accountId를 조회
- **라벨(labels)** — 없으면 생략 가능
- **우선순위(priority)** — 없으면 Jira 기본값 사용

한 번에 자연스럽게 물어보는 게 좋습니다 (7개를 하나씩 따로 묻지 말고, 필요한 항목을 한 메시지에 모아서 질문하세요).

### 3. 제목/본문 조립

**제목(summary):**
```
[업체명][엔드유저][포맷] 요약내용
```
엔드유저가 없으면: `[업체명][포맷] 요약내용`

**본문(description)은 아래 마크다운 템플릿 그대로 조립하세요:**

```
## 업체 문의내용
{정리된 문의 내용}

## 엔진 브랜치
PR/IntX_Weboffice
```

**"업체 문의내용" 채우는 법**: 메일 내용의 핵심(실제 문의/보고 내용)을 요약하거나 재구성하지 말고 그대로 옮기세요. HTML 태그는 읽기 쉬운 텍스트로 정리하세요.

단, 사내에서 여러 번 전달(Fw:/Re:)된 메일은 전달자마다 인사말·서명·Outlook 자동 전달 헤더(`보낸 사람/보낸 날짜/받는 사람/참조/제목` 같은 블록)가 겹겹이 붙어 있습니다. 이런 전달 wrapper는 담당자가 이슈를 읽을 때 아무 정보도 주지 않는 노이즈이므로 제거하고, 실제 문의/보고 내용(및 그 위에 붙은 CS·영업 담당자의 짧은 코멘트)만 남기세요. 어디까지가 wrapper이고 어디부터가 알맹이인지 애매하면, 본문 재구성 없이 다듬은 결과를 사용자에게 먼저 보여주고 확인받으세요 (4단계에서 어차피 전체를 보여주므로 자연스럽게 됩니다).

가벼운 스타일링을 더하세요 (내용 자체를 바꾸지 않는 선에서):
- CS/영업 담당자가 남긴 전달 코멘트(예: "아래와 같은 문의가 인입되어 전달드립니다")는 마크다운 인용 블록(`>`)으로 감싸서, 실제 최종 문의자의 발언과 시각적으로 구분되게 하세요.
- `setEditMode(1)` 같은 함수 호출, API 이름, 설정값 등 코드성 표현은 백틱으로 감싸세요.
- 문장 자체의 어순이나 표현은 바꾸지 마세요 — 스타일링은 감싸기(인용/코드)만 하고, 재작성하지 않습니다.

메일 발신자/수신일시/원제목 같은 메타정보를 따로 footer로 덧붙이지 마세요 — 전달 체인이 있는 메일은 "마지막 전달자"와 "실제 문의자"가 다른 경우가 많아 오히려 혼란을 주고, 정작 필요한 출처는 이미 본문 안(예: `[VOC] {이메일}`)에 남아있는 경우가 많습니다.

**"엔진 브랜치" 섹션**: 현재 팀 관례상 `PR/IntX_Weboffice`로 고정합니다. 포맷(HWP/WORD/SHEET/SLIDE)이 달라도 값은 바꾸지 마세요 — 만약 사용자가 다른 브랜치를 언급하면 그 값을 대신 쓰고, 이 스킬 문서도 함께 업데이트할지 물어보세요.

첨부파일이 있으면 맨 끝에 섹션을 하나 더 추가하세요:
```
## 첨부파일
{파일명1}, {파일명2} (원본 메일 참조 — 자동 첨부되지 않음)
```
첨부파일이 없으면 이 섹션 자체를 넣지 마세요.

### 4. 생성 전 확인

Jira 이슈는 팀 전체에 보이는 기록이므로, `createJiraIssue`를 호출하기 전에 완성된 제목과 본문 전체를 사용자에게 보여주고 확인을 받으세요. 사용자가 승인하면 그다음에 생성하세요.

### 5. 이슈 생성

`mcp__atlassian__createJiraIssue`를 다음 값으로 호출:
- `cloudId`: `polarisoffice.atlassian.net`
- `projectKey`: `WO`
- `issueTypeName`: `Task`
- `summary`: 위에서 조립한 제목
- `description`: 위에서 조립한 본문 (contentFormat은 기본값인 markdown 사용)
- `assignee_account_id`: 조회한 accountId (있는 경우)
- `additional_fields`: `{"priority": {"name": "..."}, "labels": [...]}` (값이 있는 것만 포함)

### 6. 결과 보고

생성된 이슈 키를 받으면 `https://polarisoffice.atlassian.net/browse/{이슈키}` 형태의 링크로 사용자에게 알려주세요.
