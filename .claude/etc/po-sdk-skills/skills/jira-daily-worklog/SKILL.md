# Jira 일일 업무기록 (WOA-530 Worklog)

퇴근 전 개인 Jira 업무기록 이슈에 그날 근무 시간과 한 일을 Jira **Worklog**로 등록하는 스킬입니다. 이슈 코멘트가 아니라 Worklog 기능을 씁니다 — 아래 배경 참고.

## 배경

- **대상 이슈는 `WOA-530`("[작업기록] WebOffice 공통")으로 고정**입니다. 사용자가 명시적으로 다른 이슈 키를 지정하지 않는 한 이 이슈를 사용하세요.
- **Worklog를 쓰는 이유**: 이 이슈는 이미 실사용 중이며(2026-08-04 확인 시점 319건), 지금까지 전부 코멘트가 아니라 Jira 네이티브 **Worklog**(`timeSpent` + 코멘트)로 기록돼 있었습니다. 코멘트(`addCommentToJiraIssue`)를 쓰지 말고 반드시 `mcp__atlassian__addWorklogToJiraIssue`를 사용하세요.
- **Worklog 코멘트 형식**: 서술형 문장이 아니라 그날 한 일을 짧은 불릿 리스트로 나열하는 방식이 기존 관례입니다 (예: "PC 세팅", "작업 환경 세팅" 식). 이 스킬에서도 동일하게 불릿 리스트로 작성하세요.
- **HR 커스텀필드 관련 참고(문제 없음, 조치 불필요)**: 이 이슈에는 "소속팀/Project Task/업무구분 카테고리/업무구분 세부항목"이라는 HR 탭 커스텀필드 4개가 연결돼 있습니다. 2025-02-17에 이 필드들이 비어 있어서 사내 자동화(Automation for Jira)가 "작업기록이 정상적으로 등록되지 않았으니 삭제 후 재등록해달라"는 코멘트를 남긴 이력이 있습니다. **2026-08-04 확인 결과 이 4개 필드는 이미 이슈 레벨에 값이 채워져 있고, `addWorklogToJiraIssue` 도구에는 애초에 이 필드들을 다룰 파라미터가 없습니다** — 즉 매번 신경 쓸 필요 없이 정상 등록됩니다. 다만 혹시 등록 후 비슷한 자동화 경고 코멘트가 다시 달리면, 임의로 삭제·재등록하지 말고 사용자에게 그대로 알리고 판단을 맡기세요.

## 오늘 한 일을 파악하는 방법

**1차 소스는 항상 현재 대화 컨텍스트**입니다 — 이번 세션에서 실제로 무엇을 했는지가 가장 정확한 근거입니다. 세션 기억만으로 하루 전체가 커버되지 않거나 애매한 경우에만, 아래 소스로 보완 확인하세요. 확인 없이 아래 소스를 전부 순서대로 조회할 필요는 없습니다 — 세션 컨텍스트로 이미 충분하면 생략 가능합니다.

| # | 소스 | 확인 방법 |
|---|---|---|
| 1 | Outlook 메일 (발송/초안) | `mcp__outlook__list-mail-folder-messages` 등으로 Sent Items 폴더에서 `sentDateTime`이 오늘인 것 + Drafts 폴더에서 오늘 생성된 초안 (`vendor-mail-reply`, `outlook-draft-reply`, `sdk-license-notice` 결과물) |
| 2 | Jira 이슈 생성 | JQL `project = WO AND reporter = currentUser() AND created >= startOfDay()` (`mail-to-jira-issue` 결과물). **주의**: 오늘 기존 이슈에 단 코멘트는 JQL로 깔끔하게 걸러낼 방법이 없으므로(누가 언제 코멘트 달았는지 직접 필터링하는 절이 없음) 코멘트 여부는 세션 기억에 의존하세요 — 별도로 조회하려 하지 마세요. |
| 3 | SharePoint 릴리즈 폴더 새 버전 | `sharepoint-version-folder-copy` 결과물 확인: 릴리즈 폴더(`root:/PolarisWebOffice/릴리즈:`, 사이트 `infrawareo365.sharepoint.com`/`sites/i-Drive-PolarisWebOffice`) 하위 항목 중 `createdDateTime`이 오늘이고 `createdBy.user.email`이 `dave.g.park@polarisoffice.com`인 것 |
| 4 | GitHub 커밋/PR | `gh search commits --author=dave-g-park --author-date=>=YYYY-MM-DD` 및 `gh search prs --author=dave-g-park --created=>=YYYY-MM-DD` (오늘 날짜, 로그인된 `dave-g-park` 계정이 접근 가능한 모든 조직/레포 대상) |
| 5 | Outlook 캘린더 일정/회의 | 오늘 날짜로 `mcp__outlook__list-calendar-events` (또는 `get-calendar-view`)로 오늘 잡힌 일정·회의 목록 확인 |

**의도적으로 제외한 소스** (근거로 쓰지 마세요):
- **SDK 라이선스 발급 이력** (`sdk-license-issue`) — sdkbuilder `getAllDeployInfo` 응답에는 발급자(누가 눌렀는지) 필드가 아예 없고, 팀 공용 툴이라 오늘자 항목이 있어도 사용자 본인이 한 것인지 알 수 없습니다.
- **다른 Jira 이슈의 Worklog** — 사용자는 WOA-530 외 다른 이슈에는 작업 기록을 남기지 않습니다.
- **`.claude/local/clipboard.md`** — 메일 문구 작성 스킬들이 결과물을 임시로 적어두는 보조 파일일 뿐 실제 작업 산출물이 아니고, 매번 덮어써서 이력도 없습니다.

**Claude Code 스킬 작업(이 저장소 `.claude/skills/` 아래 새 스킬 추가, 기존 스킬 수정 등)도 오늘 한 일에 포함합니다.** "클로드 스킬"이라는 키워드와 스킬 이름을 넣고, 그 스킬이 실제로 무엇을 하는지/무엇을 개선했는지도 짧게 풀어서 씁니다. 아래 "항목 표기 형식" 참고.

## 항목 표기 형식 (일관성 유지)

같은 종류의 작업은 매번 같은 형식으로 씁니다 — 예를 들어 고객 문의 회신이 여러 건이면, 사람마다 형식이 달라지지 않도록 아래 템플릿을 그대로 따르세요.

- **고객 문의 회신**: `고객 문의 회신 (받는사람[/소속] — 주제)`
  - 받는사람 이름을 알면 이름을 쓰고, 소속(회사)도 알면 `이름/소속`으로 붙입니다. 이름을 모르고 회사만 알면 회사명만 씁니다.
  - 주제는 실제 메일 핵심 내용을 짧게(메일 본문/제목 확인해서 구체적으로 — "문의 회신"처럼 뭉뚱그리지 않기).
  - 예: `고객 문의 회신 (김효진님/위세아이텍 — SDK 라이선스 안내)`, `고객 문의 회신 (지엔기술 — 문단 간격 설정 API 지원 완료 안내)`
- **Claude 스킬 작업**: `클로드 스킬(스킬명) 신규개발/수정 — 무엇을 했는지`
  - 스킬 이름을 넣어도 되지만, 반드시 "클로드 스킬"이라는 표현과 함께 무엇을 하는/개선한 스킬인지도 같이 씁니다.
  - 예: `클로드 스킬(outlook-draft-reply) 수정 — 메일 초안 저장 시 줄바꿈 깨짐 수정, 인용내역 민감정보 경고 추가`
- **SharePoint 릴리즈 폴더 공유**: `SharePoint 릴리즈 폴더 고객사 담당자 공유 추가 (N건)`

같은 카테고리 안에서 여러 건을 적을 때는 위 템플릿의 구조(괄호/구분기호 순서)를 통일하세요 — 한 건은 `이름 — 주제`, 다른 건은 `이름/소속 — 주제` 식으로 섞이지 않게 합니다.

## 절차

### 1. 근무 시간 확인 (필수)

사용자에게 직접 물어보세요 (예: "오늘 몇 시간 근무하셨나요?"). 임의로 채우지 않습니다. 소수 시간(예: "7.5시간")은 `Xh Ym` 형식으로 변환하세요 (7.5시간 → `7h 30m`). Jira `timeSpent` 파라미터가 인식하는 형식(`8h`, `7h 30m`, `30m`)으로 정규화해서 사용합니다.

### 2. 오늘 한 일 정리

위 "오늘 한 일을 파악하는 방법" 표를 참고해서 불릿 리스트 초안을 만듭니다. 지어내지 않습니다 — 근거가 불확실한 항목은 넣지 말고, 애매하면 "오늘 이런 것도 하셨나요?" 식으로 사용자에게 확인하세요. **자세히 쓸 필요는 없습니다** — 무엇을 했는지 알아볼 수 있는 짧은 항목이면 충분합니다 (기존 관례와 동일, 예: "고객 문의 회신 (김효진님 — SDK 라이선스 안내)", "Jira 업무기록 자동 등록 기능 신규 개발").

### 3. 초안 확인

완성된 근무 시간(`timeSpent`)과 작업 목록(불릿 리스트)을 사용자에게 그대로 보여주고 최종 승인을 받습니다. 실제 데이터가 생성되는 작업이므로 이 확인 없이 다음 단계로 넘어가지 않습니다.

### 4. Worklog 등록

`mcp__atlassian__addWorklogToJiraIssue`를 다음 값으로 호출합니다:
- `cloudId`: `polarisoffice.atlassian.net`
- `issueIdOrKey`: `WOA-530` (사용자가 다른 이슈를 지정한 경우 그 값)
- `timeSpent`: 1번에서 정규화한 값
- `commentBody`: 3번에서 확정한 불릿 리스트 (마크다운)
- `contentFormat`: `markdown`

### 5. 결과 보고

등록된 worklog 내용과 `https://polarisoffice.atlassian.net/browse/WOA-530` 링크를 사용자에게 알려줍니다. 만약 등록 후 자동화가 "필드 누락으로 재등록 필요" 같은 코멘트를 남기면(배경 섹션 참고), 임의로 삭제·재등록하지 말고 사용자에게 그대로 알립니다.

## 절대 하지 말 것

- 근무 시간을 묻지 않고 임의로 채우지 않습니다.
- 오늘 한 일을 지어내지 않습니다 — 근거 없는 항목은 넣지 않고, 애매하면 사용자에게 확인합니다.
- 최종 확인 없이 바로 `addWorklogToJiraIssue`를 호출하지 않습니다.
- 이슈 코멘트(`addCommentToJiraIssue`)로 등록하지 않습니다 — 반드시 Worklog(`addWorklogToJiraIssue`)를 사용합니다.
- SDK 라이선스 발급 이력, 다른 이슈의 Worklog, `.claude/local/clipboard.md`를 오늘 한 일의 근거로 사용하지 않습니다.
- Claude Code 스킬 작업을 적을 때 스킬 이름만 달랑 쓰지 않습니다 — "클로드 스킬" 키워드와 함께 무엇을 하는/개선한 스킬인지 풀어서 씁니다.
- 같은 카테고리(예: 고객 문의 회신) 항목들의 표기 형식을 건마다 다르게 쓰지 않습니다 — "항목 표기 형식" 섹션의 템플릿을 통일해서 적용합니다.
- HR 커스텀필드 관련 자동화 경고가 다시 뜨면 임의로 삭제·재등록을 시도하지 않습니다.
