## 확인 순서 (반드시 이 순서대로 질문)

### 1. 이전 라이선스 발급 이력

이 고객사에 이전에 라이선스를 발급한 적이 있는지 먼저 묻습니다.

- **없음** → 별도 문구 추가 없이 다음 단계로.
- **있음** → 이전에 나간 버전이 `v1.2.x`인지 `v1.4.x`인지 묻습니다.
  - **v1.2.x였던 경우**: 메일 인사말(`폴라리스오피스 박근우입니다.`) 바로 다음, `【SDK 파일 전달 방식 안내】` 섹션 앞에 아래 문구를 추가합니다.
    ```

    ```
  - **v1.4.x였던 경우**: 별도 문구 추가 없음.

### 2. 다운로드 버전

이번에 전달할 SDK 버전을 묻습니다 (예: `v1.4.28`). 템플릿의 "다운로드 버전" 항목과, 5번에서 샘플 코드 안내를 포함하기로 했다면 그 안의 버전 문자열에도 **동일한 값**을 반영합니다.

### 3. 라이선스 키 — 도메인(IP)

라이선스 키에 등록할 도메인 또는 IP를 묻습니다 (예: `localhost, 127.0.0.1, xxx.com`). 이때 **이 라이선스가 개발용인지 운영용인지도 함께 확인**합니다.

- **개발 라이선스인 경우**: 도메인(IP) 목록에 `localhost`와 `127.0.0.1`이 반드시 포함되어야 합니다. 사용자가 준 목록에 둘 중 하나라도 빠져 있으면, 빠져 있음을 알리고 추가할지 확인합니다 — 임의로 추가하지 않습니다.

### 4. 라이선스 키 — 만료일

만료일을 묻습니다 (예: `2026-10-20` 또는 `영구`).

- **개발 라이선스인 경우 만료일은 절대 `영구`가 될 수 없습니다.** 3번에서 개발 라이선스로 확인됐는데 사용자가 `영구`라고 답하면, 그대로 채우지 말고 개발 라이선스는 영구 발급이 불가하다는 점을 알리고 실제 만료일을 다시 확인합니다.

### 5. SDK 샘플 코드 실행 방법 포함 여부

샘플 코드 실행 방법 안내를 메일에 포함할지 묻습니다.

- **포함**: `【SDK 연동 안내】` 섹션과 `【SDK 라이센스키 적용 방식 안내】` 섹션 사이에 아래 블록을 삽입합니다 (`{버전}`은 2번에서 받은 다운로드 버전으로 치환).

